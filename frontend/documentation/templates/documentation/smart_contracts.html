{% blocktrans trimmed %}Tancoin uses UTXO for the coin, like Bitcoin. Contracts add stored bytecode and storage, run by the Tancoin Virtual Machine (TVM).{% endblocktrans %}

{% endblock %} {% block docs_content %}

{% trans "Not the same as Ethereum EVM" %}

{% blocktrans trimmed %}TVM bytecode is not compatible with Solidity. You cannot paste Ethereum compiler output here. The goal is a small, clear machine you can read and extend.{% endblocktrans %}

{% trans "Deploy and call" %}

  1. {% blocktrans trimmed %}Deploy: an output of type contract_deploy carries bytecode in payload. After the block is applied, the contract id is derived from the transaction id and output index.{% endblocktrans %}
  2. {% blocktrans trimmed %}Call: a contract_call output points at that id and passes calldata. The VM runs when the block is applied and may update storage.{% endblocktrans %}
  3. {% blocktrans trimmed %}Fees: many contract outputs have value zero. The miner still collects fees from the difference between inputs and outputs, like normal transfers.{% endblocktrans %}

{% trans "Gas and limits" %}

{% blocktrans trimmed %}Each opcode costs gas. Storage writes cost more. If gas runs out, the call fails and storage does not stay in a half-updated state for that call.{% endblocktrans %}

{% trans "Execution context" %}

{% blocktrans trimmed %}Contracts can read block time from an opcode and the caller hash from the first input’s public key script. This is similar in idea to msg.sender and block.timestamp on Ethereum.{% endblocktrans %}

{% trans "Testing" %}

{% blocktrans trimmed %}Deploy with POST /api/contracts/deploy/, then mine a block. List contracts with GET /api/contracts/. Call with POST /api/contracts/call/ and hex calldata.{% endblocktrans %}
